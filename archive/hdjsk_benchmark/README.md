# H=40：保存済み入力でDenseとCSRの速度を比較する

`hdjsk_benchmark.ino` と `benchmark_parameters.h` を同じ `hdjsk_benchmark` フォルダに置きます。
このスケッチは保存済みの128入力を使って計測するので、チャート操作は不要です。
接続しているセンサ・LED・ボタンのピンは操作しません。

## Arduino IDEで行うこと

1. `hdjsk_benchmark.ino` を開き、Arduino UNO R4 WiFiと接続ポートを選ぶ。
2. 検証して書き込む。
3. シリアルモニタを **9600 baud・改行あり** にする。案内が見えなければRESETを押す。
4. 半角の **`t`** を送信する。
5. `BENCHMARK START` から `BENCHMARK END` までのログを保存する。

固定入力チェックが両方PASSで、`TIMING VALID: YES` となることを確認します。
チェックがFAILの場合は、速度計測を実行せずログを表示します。

## 計測内容

- Denseは元の学習済みH=40モデル、CSRは暫定閾値 `0.2449173554778099` の枝刈り後モデルです。
- 同じバイアスを共有し、Denseの重みとCSRの値・索引はすべてconst配列として通常のポインタで読みます。
- 入力は検証用2回×64マスの128組。元のNN入力をFP32で保存しています。
- 計測前に128入力すべてでDense・CSRそれぞれのPC参照出力と比較します。
  許容差は絶対誤差 `1e-5` ＋ 相対誤差 `1e-5` です。
- 正常なら各方式を10回ウォームアップし、100回の推論を5組計測します。
- 同じ組では両方式へ同じ100入力を同じ順で与えます。開始位置は組ごとに100ずつ進め、128で循環させます。
- 奇数組はDense→CSR、偶数組はCSR→Denseの順で計測します。
- `micros()` の差分はuint32で計算し、タイマの一周をまたぐ場合にも対応します。
- 時間には推論関数の呼出、入力位置の選択と出力への書込を含みます。センサ、校正、RGB整数化、表示は含めません。
- 結果のチェックサムは各組の計測終了後に計算します。すべての表示も全組の計測後に行います。
  コンパイラによる推論の削除や計測区間外への移動を防ぐため、noinline指定・出力の消費・コンパイラバリアを使用します。

ログには5組それぞれの合計時間（us）と100で割った1推論当たりの時間を出します。
平均と標本標準偏差（5組、分母4）、Denseに対するCSRの時間増減率も表示します。
負の時間増減率はCSRが速いことを表します。ゼロ時間を含む場合はタイマ分解能上の問題として無効とします。
チェックサムは結果が使われていることの確認用です。枝刈りでモデルが変わるため、DenseとCSRで同じ値になるとは限りません。

## 容量・精度との区別

`MODEL BYTES` は各モデル配列の `sizeof` の合計です。Denseは7,692 byte、CSRは1,149 byteです。
両モデルが同時に入っているため、この結合ビルド全体のRAM・フラッシュ使用量から
各方式を単独搭載したときの使用量は比較できません。単独ビルドの記録は別に取ります。
同じバイアスを共有するので、両モデルの個別容量の単純合計とも異なります。

計測用の入力・参照出力は合計4,608 byte、出力保存バッファは1,200 byteあります。
これらはモデル容量に含めません。以前の12入力・各層の参照データ4,128 byteはこのビルドに含めていません。
const配列の実際の配置はツールチェーン依存なので、単独ビルドのRAM・フラッシュ比較でも配置を確認します。

この計測で分かるのは保存済み入力での推論時間です。色の精度や校正の問題が解決したことは意味しません。
2回目の全0入力6マスと、暫定閾値でその回のMSEが約35.4%増える制約は維持しています。
最終的な精度比較には別の最終評価用チャートを使い、結果を見てその同じデータで閾値を選び直しません。

## 再生成と確認範囲

リポジトリ直下で `python3 pruning/export_benchmark_arduino.py` を実行するとデータヘッダを再生成できます。
元のモデル・検証CSVのSHA256と選択結果を確認し、CSRから復元した重みの一致も検査してから出力します。
時計周波数のマクロ、コンパイラの版、入力とモデルのSHA256は実機ログに出します。
ボード・コア・IDEの版、Arduino IDEに出るビルド使用量も実験記録へ保存してください。

クラウド側の時計によるテスト値は実機の速度として保存しません。実際の時間はUNO R4 WiFiのログで確認します。
