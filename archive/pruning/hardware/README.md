# 実機で受信した結果

`h40_csr_self_test_01.txt` は、ユーザーのArduino UNO R4 WiFiから受信した起動ログです。
2026年10月30日（日本時間）にチャットで受信しました。正確な実行日時・IDEやコアの版は未記録です。

- H=40、暫定閾値 `0.2449173554778099`、非ゼロ重み数129。
- CSRの各モデル配列に実機で `sizeof` を適用した合計は1,149 byte。
- Denseの7,692 byteは、このスケッチでは参照モデルの配列容量を表示したものです。
- CSRの行ポインタ・列番号・非ゼロ値のチェックはPASS。
- 固定12入力の各層をPCの枝刈り後Dense参照値と比較したチェックもPASS。
- 最大絶対誤差は隠れ層1が `1.4e-7`、隠れ層2が `1.7e-7`、出力が `2.4e-7`。

設定した許容差は絶対誤差 `1e-5` ＋ 相対誤差 `1e-5` です。
今回の最大誤差はいずれも絶対誤差分の `1e-5` 未満です。
モデルのSHA256・閾値・容量は、保存済みの閾値選択結果と一致します。

これはCSR実装の数値計算の確認です。センサ校正、絶対的な色精度、推論速度、
ビルド全体のRAM・フラッシュ使用量を確認した結果とは区別します。
検証2回目の全0入力やMSE増加についての制約は、`../validation/README.md` に記録しています。

黒→白→同じ黒の追加確認は `h40_black_return_01.txt` とJSONに保存しています。
センサは固定し、紙だけを動かしたとのユーザー申告です。黒登録値は `(17,14,10.9)`、
再読取の正規化値は `(0.06932409,0.12882447,0.16785714)` でした。
クリップされていないので逆算すると再読取の生データは約 `(29,30,25)` です。
これは直接表示されたRAWの記録ではなく、校正値と正規化値からの推定です。
同じ黒の登録値と再読取値がNN推論の前で異なっており、原因の切り分けが残っています。
待ち時間と繰返しの生データを見る診断は `../../diagnostics/sensor_stability/` に用意しています。


`sensor_stability_01_log.txt`は、デジタル点灯で黒→白→黒を読み取った実測です。
全30組を `sensor_stability_01.csv`、条件ごとの平均・標本標準偏差・最小最大・時間変化を
`sensor_stability_01_summary.json`、図を `sensor_stability_01_plot.png` に保存しています。
白のRは最初220.5、最後143.0で約35.1%低下しました。200 msの区間だけでも164.0から143.0へ動いています。
最後の黒も、200 ms区間内でRが25.6から36.0へ増加しました。
このデータから待ち時間200 msを安定条件として採用することはできません。
10 msが先、200 msが後という順序なので、時間経過と待ち時間の影響も分離できていません。
センサは固定し、紙は手で支えていたとのユーザー申告です。
紙の位置・角度や手の影は原因候補ですが、まだ確定していません。
次は紙も固定して手を離し、同じスケッチで白だけを1回読む対照確認へ進みます。
