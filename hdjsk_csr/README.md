# H=40 枝刈り＋CSR版：最初の実機チェック

最初に行う作業は、書き込み後に出る自動チェックの表示確認です。
この段階の確認には、チャートの読み取り操作は必要ありません。

## MacのArduino IDEで行うこと

1. `hdjsk_csr.ino` と `model_parameters_csr.h` を、`hdjsk_csr` という同じフォルダへ置く。
2. `hdjsk_csr.ino` を開き、ボードを **Arduino UNO R4 WiFi**、ポートを接続先にする。
3. 「検証」でコンパイルし、成功したら書き込む。
4. シリアルモニタを **9600 baud・改行あり** にし、Arduinoの **RESET** を押す。
5. `CSR CHECK START` から `CSR CHECK END` までの表示をコピーして保存する。

表示の主要部分は次のようになります。

```text
========== CSR CHECK START ==========
CSR MODEL: PROVISIONAL
H=40
THRESHOLD=0.2449173554778099
MODEL BYTES: Dense=7692 CSR=1149
MODEL NNZ=129
...
CSR INDEX CHECK: PASS
CSR SELF TEST: PASS (12 cases)
MAX ABS ERROR: L1=... L2=... OUT=...
SELF TEST REFERENCE BYTES=4128
=========== CSR CHECK END ===========
```

その後に画像サイズの入力待ちになります。まずは上記の起動ログを確認します。
チェックがFAILの場合は処理を停止するので、ログを保存して原因を確認してください。
Arduino IDEに出るフラッシュ・RAM使用量も、ビルド全体の記録として保存してください。

## 自動チェックの内容

3層のCSR配列について、行ポインタの先頭・終端・順序、列番号、非ゼロ値を確認します。
8通りの入力の端点と、検証用1回目から固定した4入力、合計12入力で各層を計算し、
PC上の枝刈り後Denseが出した参照値と比較します。参照値はCSRループから生成していません。
許容誤差は、RGBへのクリップ・整数化前の値に対して絶対誤差 `1e-5` ＋ 相対誤差 `1e-5` です。
隠れ層のReLU、出力層の線形出力、バイアスを先に加える順序はDenseと同じです。

このPASSは「選んだ重みの計算がPCの参照値と一致する」という実装確認です。
センサ校正や色の精度を確認したという意味ではありません。

## モデル容量と確認用データ

`MODEL BYTES` のCSR容量は、3層のFP32値・FP32バイアス・uint8列番号・uint16行ポインタの
各配列に実際に `sizeof` を適用した合計です。Dense側の数値は参照モデルの配列容量です。
モデルの129個の非ゼロ重みはFP32であり、INT8への量子化は行っていません。

固定入力と各層の参照値は確認専用の配列で、合計4,128 byteあります。
これらやシリアル表示、センサ用の保存配列、コード、配置はビルド全体の使用量に含まれますが、
モデル配列容量の1,149 byteには含めません。
正式な容量・速度比較では、チェックに合格した後に `ENABLE_CSR_SELF_TEST` を `0` にし、
参照配列を除いた状態でもビルド全体のRAM・フラッシュを記録します。
DenseとCSRで、配列のconst指定や配置・読出方法もそろえる必要があります。
このスケッチには推論速度の計測処理はまだ追加していません。

## 暫定候補であること

元のモデルは `../hdjsk/model_parameters.h` の既存H=40モデルです。
検証用2回の平均MSE条件では選択されましたが、2回目には6色が同じ全0入力となり、
その回単独ではMSEが約35.4%増えます。この候補は記録済み条件に対する暫定値です。
測定条件や絶対的な色精度が十分であるとは扱いません。
測定記録と限界は `../pruning/validation/README.md` に保存しています。

起動チェック後にチャートを読む場合は、従来と同じくサイズ入力、黒で `b`、白で `w`、
各色で `r` を送信します。前処理、読取回数、待機時間、PPM変換、入力一覧の形式はDense版と同じです。
最終評価には閾値選択に使った画像とは別のチャートを用い、最終評価結果で閾値を選び直しません。

## ヘッダの再生成

リポジトリ直下で `python3 pruning/export_csr_arduino.py` を実行すると再生成できます。
元のモデル・検証CSVのSHA256を選択結果と照合し、CSRから復元した重みとバイアスが
選択された枝刈り後Denseと一致することを確認してから書き出します。
モデルや検証データを変更したときは、先に閾値選択をやり直してください。
非ゼロ数0の層についてはC++の空配列と容量計上を別途決める必要があるため、この出力ツールは停止します。

クラウドでは、PC上でのC++コンパイル、各層・RGB出力の比較、シリアル操作の模擬確認を行っています。
UNO R4 WiFi向けの実ビルド・書き込み・実機での自動チェック結果は、MacのArduino IDEとボードで確認します。
