# 紙を新しく読み取り、全6条件の精度を比較する

手元の**学習用3×3チャート**を読み直します。
1回のRGB読取値から、40・60・100次元のDense/CSR全6条件を計算します。
速度測定で使用した新しい33組の学習済み重みと閾値をそのまま使い、再学習や閾値の選び直しはしません。

## 最初の1回

1. `fresh_scan_all` フォルダへ [fresh_scan_all.ino](fresh_scan_all.ino) と
   [models_all.h](models_all.h) を保存します。
2. Arduino UNO R4 WiFiへ書き込み、シリアルモニタを **9600 bps** にしてRESETを押します。
3. `FRESH SCAN CHECK START`〜`END` の3モデルの確認で
   **`ALL MODELS CHECK: PASS`** が出ることを確認します。
4. 画像サイズは3×3に設定済みです。チャート左下の**黒を当てて `b`**、右下の**白を当てて `w`** を送信します。
5. **左上→右へ上段3色、中段3色、下段3色**の順に、各色を当てて **`r`を1回ずつ**送信します。
   下段は黒・灰・白です。紙は手持ちで扱い、送信前に当て方をそろえ、読取中は動きを抑えます。
6. 9色後に出る **`FRESH CAPTURE START`〜`FRESH CAPTURE END` を丸ごと保存**します。
   MSE6行、PPM6枚、9色の生値・読取終了時の起動後時刻、校正値、NN入力がまとめて出ます。

`--- CSR40補正後 ---` の各色表示は進捗確認用です。
全6条件の最終結果は9色を読み終えた後のまとめにあります。

## もう1回読む

半角 **`n`** を送り、黒 `b`・白 `w` の登録から同じ9色を独立に読み直します。
`CAPTURE=2` になります。まず1回分を保存し、同じ手順で2回分を集めることを目標にします。
RESETすると番号は1へ戻るため、続けて測る場合は `n` を使います。

## 結果の意味

ここでの入力は、その場で紙から新しく取得した値です。
前の `compare_h40` などで表示した保存済み学習入力のMSEと分けて記録します。
1回の読取から全6条件を計算するため、条件間で手持ちの位置ずれによる入力差を混ぜずに比較できます。
同じ入力を使った6条件の出力は6回の独立測定ではありません。
`n` で読み直した回数を物理的な反復数として数えます。

チャートの色は学習に使った9色なので、これは**学習チャートを新しく読み直した精度**です。
独立した最終評価ではなく、当初計画の各条件10回の独立した読取を完了した結果でもありません。
正解RGBは元Notebookの保存済み表示から復元しており、元PNGとの数値照合は未実施です。
参照値の出典は [provenance.json](../../retraining/data/provenance.json) にあります。

センサの配線と読取・前処理は元のスキャナのままです。
A0、LED R8/G6/B7、analogWrite 255/0、待機10 ms、各色チャンネルADC10回平均を使います。
紙を固定することは要求しません。
このプログラムの速度は測定せず、推論時間には先に保存した専用ベンチマークの値を使います。
全6モデルを含むスケッチのFlash・RAM使用量を、各方式単独の使用量とは扱いません。

## 実装の確認

ヘッダは各モデルの重み・検証データのSHA256を確認して生成し、CSRからの復元一致と実配列容量も検査します。
起動時には各Hで索引と12固定入力のDense/CSR出力を確認します。
PC上ではC++11のASan・UBSanを有効にして各417入力の全6出力、
2回の模擬校正・9色読取、PPMとMSE、NN入力、nでの再開始を確認しました。
模擬読取の値は実験結果として保存しません。
[fresh_scan_verification.json](../fresh_scan_verification.json) はPC上の検証記録です。
実物の紙の読取は現在1回分を受領し、[fresh_readings](../fresh_readings/README.md) に保存しました。
起動時のチェック部分のログは未受領ですが、新しい9入力での6モデルの出力はPCの再計算と一致しています。
