# 精度を優先する追加探索

元の容量優先候補は、紙の再読取2回でDenseに対してMSEが約19〜25%増えました。
精度維持の目安（増加5%以下）を満たしていないため、同じDense重みから枝刈りを弱めた候補を探索します。
元の重み・候補・測定記録は上書きしません。

## 改善する対象

ここではCSRの出力を元のDenseへ近づけます。
Dense自体の再読取MSEが約1,700〜2,000ある問題は残り、MSEが50などになるという結果ではありません。
絶対的な色精度には、読取条件と学習入力の違いや、複数の読取条件への学習を別に検討する必要があります。

## 選択した候補

元の33組の学習MSEをDense比5%以内、元の検証チャート各読取回のMSEもDense比5%以内とします。
さらに、入力各成分0〜1を0.125刻みとした固定729入力で、Denseとのクリップ後出力差を最大0.5/255以下にします。
この全条件を満たす候補でCSR容量を最小にしました。
容量が小さい順に検査し、最初に通過する候補を選びます。MSEの単調性は仮定しません。
グリッド上での条件なので、すべての入力で同じ差に収まるという保証ではありません。

| H | 旧閾値 | 追加候補の閾値 | Dense byte | 追加CSR byte | 容量削減率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 40 | 0.1387345567 | 0.0011764123 | 7,692 | 4,774 | 37.94% |
| 60 | 0.1484270990 | 0.0020613672 | 16,332 | 4,424 | 72.91% |
| 100 | 0.2595954686 | 0.0011608397 | 43,212 | 24,304 | 43.76% |

多くの重みを残すため前よりモデルが大きくなり、速度も再測定が必要です。
追加候補の実機推論時間・ビルド使用量は未測定です。旧候補の値を流用しません。

## 次の実機確認

MSEを優先し、まず新しい紙の読取を行います。
[fresh_scan_all](fresh_scan_all) の `fresh_scan_all.ino` と **`models_precision.h`** を同じフォルダへ保存します。
UNO R4 WiFiへ書き込み、9600 bpsで起動時の `ALL MODELS CHECK: PASS` を確認します。
3×3の黒b・白wで校正し、9色をrで読みます。
全6条件の画像とMSEを出します。新スキャナのCAPTURE番号は書き込み後に1から始まります。
新しい測定は別段階としてこのフォルダの配下へ保存し、元の測定平均と混ぜません。
同じ学習用チャートの再読取なので、独立した最終評価にはなりません。

精度の確認後、速度は [compare_h40](compare_h40) の `compare_h40.ino` と
**`parameters_precision.h`** を同じフォルダへ置き、書き込み後に9600 bpsで **`t`** を送信します。
`PRUNING_STAGE=EXPLORATORY_PRECISION_FOLLOW_UP`、H=40、CSR=4774 byteが新候補の識別情報です。
`BENCHMARK START`〜`END` を保存します。
同じ操作の [compare_h60](compare_h60) と [compare_h100](compare_h100) も用意しています。

## 再生成と確認

ルールは [protocol.json](protocol.json)、凍結した選択結果は `selection/h40` 等へ保存しています。
NumPyのあるPythonでリポジトリ直下から実行できます。

```sh
python3 experiment_today/precision_followup/build_firmware.py
python3 experiment_today/precision_followup/replay_prior_captures.py
```

PCで3モデルの比較スケッチと全6条件のスキャナをC++11、ASan・UBSan有効で確認しました。
各417入力の出力比較、シリアルt、MSE表示、2回の模擬校正・9色読取を通過しています。
[verification.json](verification.json) と [fresh_scan_verification.json](fresh_scan_verification.json) はPC上の確認記録です。
