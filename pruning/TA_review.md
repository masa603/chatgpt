# TA確認用：枝刈り＋CSRのプログラム

現在の実装は既存のH=40モデルを使った暫定版です。
構成は入力3、隠れ層40・40、出力3で、隠れ層だけにReLUを使います。

## プログラムと担当する処理

| ファイル | 主な関数・内容 |
| --- | --- |
| [threshold_tools.py](threshold_tools.py#L58) | `prune()` が枝刈り、`save_csr_npz()` がCSR配列への変換。閾値候補の生成と検証MSEの比較も含む。 |
| [export_csr_arduino.py](export_csr_arduino.py#L56) | 選択したCSR配列をC++ヘッダへ出力。元モデルのSHA256と、枝刈り後Denseからの復元一致を確認。 |
| [hdjsk_csr.ino](../hdjsk_csr/hdjsk_csr.ino#L110) | `csrLayer()` がCSR行列と入力ベクトルの積、`predictLayers()` が3層の推論。センサ・シリアル操作も含む。 |
| [model_parameters_csr.h](../hdjsk_csr/model_parameters_csr.h) | 実機で使う値・列番号・行ポインタ・バイアスと、固定入力チェック用データ。 |

Arduinoで開くときは `hdjsk_csr.ino` と `model_parameters_csr.h` を同じ `hdjsk_csr` フォルダに置きます。
対象ボードはArduino UNO R4 WiFiです。
Python側の一連の実行は [threshold_selection.ipynb](threshold_selection.ipynb) から行います。

## 枝刈り

3層に共通の閾値を使い、`abs(weight) < threshold` の重みを0にします。
閾値と等しい重みは残し、バイアスは変更しません。
圧縮条件ごとの再学習は行わず、同じ学習済み重みから候補を作ります。
重みの絶対値を並べ、隣接する異なる値の中間を候補にします。候補数は5個などに固定していません。

## CSR形式

各重み行列を出力ニューロンごとの行優先で変換します。

- `values`：非ゼロ重み。FP32。
- `col_idx`：各非ゼロ重みの列番号。uint8。
- `row_ptr`：各行の開始位置。uint16。先頭0、末尾は非ゼロ数K。
- `bias`：元のバイアス。FP32のまま保存。

uint8を使うのは列番号であり、重みのINT8量子化ではありません。
Arduinoでは各行をバイアスで初期化し、`row_ptr[row]`〜`row_ptr[row+1]` の範囲だけ積和を計算します。
CSRから元の枝刈り後行列を復元できることもPython側で検査します。

## 現在の候補と確認状況

閾値は `0.2449173554778099`、重み1,840個のうち非ゼロ129個です。
モデル配列容量はDense 7,692 byte、CSR 1,149 byteです。
CSR容量にはFP32の値・バイアスと列番号・行ポインタを含み、確認用データやビルド全体の使用量は含めません。

学習用とは別の検証チャート2回分で、平均MSE増加5%以下・Dense未満の容量を条件に容量最小を選びました。
平均MSEの増加は約0.64%ですが、2回目には6色が同じ全0入力となり、その回単独では約35.4%悪化します。
そのため最終採用値とはせず、暫定候補として記録しています。

実機ではCSR配列の検査と固定12入力の各層比較がPASSで、最大絶対誤差は `2.4e-7` でした。
これは数値計算の確認であり、実測の色精度が十分であるという判定ではありません。
現在のモデルは新しく測った33組から再学習したものではなく、入力の安定性と学習データの更新が残っています。
