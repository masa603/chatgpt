# V9を固定したDense／枝刈り＋CSRの比較

現在使うのは **[全8条件を1回で測るcompare_all_v9](compare_all_v9/README.md)** です。
コード `.ino` と数値パラメータ `.h` は別ファイルです。
重みの追加学習はここで止め、同じ凍結済み重みからDenseとCSRを作っています。
新しい比較プログラムの物理読取・Arduinoの推論時間はまだ受領していません。

## 次の実機操作

1. compare_all_v9フォルダへ `compare_all_v9.ino` と `comparison_parameters_v9.h` を保存してUNO R4 WiFiへ書き込む。
2. シリアル9600 bpsでRESETし、`FIRMWARE=COLOR_COMPARE_V9` と `ALL EIGHT MODELS CHECK: PASS` を確認。
3. 黒b→白wで校正し、赤・緑・青／黄・水色・紫／黒・灰・白を各rで読み取る。
4. **PAIRED CAPTURE START〜PAIRED CAPTURE END** を保存する。1回の9色入力を全8条件へ共通に使用する。
5. **t** を1回送信し、**FOUR PAIR BENCHMARK START〜FOUR PAIR BENCHMARK END** を保存する。
6. Arduino IDEのFlash使用量・グローバル変数使用量の2行も、この全8条件入りスケッチの値として保存する。

次の物理読取はnで校正から開始できます。1回の読取で得る8枚の画像を、独立した8回の測定とは数えません。
計画書の主目的は圧縮前後のMSE・容量・速度の比較です。MSE300以下という数値は計画書にはなく、利用者が追加した目標です。
目標値に達するまで再学習を繰り返す進め方から、重みを固定して比較結果を確保する進め方へ優先順位を変えました。
利用者の目標自体は、全8条件の新しい実測結果でも表示します。

## 今回受領したV8の実測

[元ログ・PPM・検算](../patch_retraining/physical_readings/capture_01/README.md) を保存しました。
全9色MSEはH40=2745.78、H60=441.11、H80=690.63、H100=1874.78で、全モデルとも300以下は未達です。
先生の元HTML、RAWからの正規化、凍結したV8のPC再生と一致しました。
同じ最新入力で旧V7も再生するとH60=385.15です。異なる読取回の実測値の差を、再学習だけの改善とは扱いません。

## V9の開発と最終学習

実測由来126組に、このV8実測9組を加えて135組・33色・14校正グループにしました。
[training135.csv](training135.csv) に全行を保存し、配布NotebookのX配列は測定値として使っていません。
新しいV8の9組は開発段階ではまとめて外し、親の学習、更新、重み・拡張幅の計算にも使っていません。
ただし失敗ログを見て方法を設計・選択した開発比較で、独立した最終評価ではありません。

構造3→H→H→3、隠れ層ReLU、線形出力、FP32を保持しました。
重みのみL1係数1e-6、Adam、学習率0.0003→0.000003のcosine、seed42です。
初めに各Hで15,000 epoch、次の3条件を比較しました。

- Huber再生：V8と同じ色・校正グループでバランスを取った正の重み、SmoothL1 beta0.05。
- 入力変動：3×3学習例の半数で、各チャンネル独立の倍率0.75〜1.30と加算変動を適用する。加算幅は `min(0.02,別ラベルの学習入力までの最短距離×0.1)`。0〜1へクリップ。灰・白には別途30%で共通倍率0.5〜1.15を適用する。
- 入力変動＋旧測定の整合度重み：上記に加え、古い3×3グループの損失重みへ5近傍の整合度を掛ける。最近の部分測定、V7、V8グループはこの減量から除外する。全行の重みは正で、削除した行はない。

初めの12条件ではH40の開発MSEが879.00残りました。
そのため、初期値の影響を調べる追加探索として、同じ入力変動＋整合度重みをV7初期値から全4Hで各15,000 epoch比較しました。
追加理由と4結果は [parent_followup.json](parent_followup.json)、初めの選択・仕上げ状態も別に保存しています。
この追加探索までを当初から固定した16条件だったとは記録していません。
全16条件は [development_results.csv](development_results.csv) に残しました。

## 固定したCSR条件

旧学習チャートとは別の8×8検証チャートの保存済み2読取・128入力を使い、
各Hの全重み絶対値の異なる値の間から候補を作成し、候補ごとに検証MSEとCSR容量を計算しました。
バイアスはFP32のままです。CSRはFP32値、uint8列番号、uint16行ポインタです。
初めの量子化計算案は公開前に、実機と同じFP32推論後のdouble倍率・四捨五入へそろえ直しました。

計画書の検証平均MSE増加5%以下・CSR容量がDense未満という条件に加え、
利用者の目標に対する補助条件として、**既に学習へ使ったV8の9色の再計算MSEも300以下**となる候補を容量の小さい順に確認しました。
この補助条件は学習データによる制約で、独立検証の証拠とはしません。
補助条件で未確認の残り候補はCSVで空欄とし、不合格と呼び替えていません。
新しい実機読取を見る前に全閾値を固定しており、その結果を見て同じデータで閾値を選び直しません。

| H | 閾値 | Dense配列byte | CSR配列byte | 学習9色のCSR再計算MSE |
| --- | ---: | ---: | ---: | ---: |
| 40 | 0.0657515749 | 7692 | 2739 | 206.00 |
| 60 | 0.0571126416 | 16332 | 6019 | 218.41 |
| 80 | 0.0433935467 | 28172 | 8884 | 298.78 |
| 100 | 0.0493337531 | 43212 | 13389 | 294.44 |

閾値・全候補・データSHA256は `selection/hH` に保存しています。
検証2読取には異なる正解色が同じ0入力になる衝突があるため、選択は**暫定**です。
容量は数値配列の合計で、全スケッチのFlash・静的RAMや索引以外の管理情報と区別します。
空のCSR層にはC++用の1要素パディングを入れ、その5byteも容量計算へ含めます。

## 時間とメモリの扱い

`t`ではセンサを読み直さず、保存した検証128入力で4組を計測します。
各方式10回ウォームアップ後、100推論×5組、Dense先行とCSR先行を交互にします。
推論と共通のチェックサム加算が計時内にあり、センサ・シリアル表示・MSE計算は含みません。
標本標準偏差の分母は5−1です。CPU上の時刻やテスト用時計をArduinoの速度として保存しません。

実機のFlash・静的RAMは、Arduino IDEに表示された全8条件入りファームウェア全体の値として記録します。
これだけで各条件単独の最小Flash・RAMを測ったとは扱いません。推論作業配列は2×100×float=800byteの宣言で、最大スタック全体の実測ではありません。
旧40/60/100の速度や古いFlash/RAMを、新しいV9の測定値として流用しません。
