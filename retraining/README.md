# 測定済み33組での再学習

紙は手持ちで扱う条件とし、すでに測った学習用3×3の9組と6×4の24組を使って再学習しました。
紙を固定できないこと、距離・角度・影の変動が残ることを制約として記録します。
センサ入力は既存の「NN入力」（0〜1）で、255で再び割りません。
4色が同じ全0入力になっていますが、33組をすべて残しています。

## 完了したPC上の結果

各モデルは3→H→H→3、隠れ層ReLU、出力層は線形です。
seed=42、50,000 epoch、Adam（学習率0.01）、重みだけへのL1係数1e-6で学習しました。
最終epochの重みを保存し、検証データによる学習・途中の重みの選択はしていません。
H=40・50・60が計画の基本条件、H=100は追加比較です。

MSEは各RGB成分について0〜255へクリップ・四捨五入した整数画像から計算しています。

| H | 学習3×3 MSE | 学習6×4 MSE | 学習33組 MSE | Dense配列byte | 保存済み検証2回の平均MSE |
| --- | ---: | ---: | ---: | ---: | ---: |
| 40 | 0.0000 | 96.2917 | 70.0303 | 7,692 | 4,499.2214 |
| 50 | 0.0000 | 96.2639 | 70.0101 | 11,612 | 3,430.7266 |
| 60 | 0.0000 | 96.2639 | 70.0101 | 16,332 | 2,065.9063 |
| 100（追加） | 0.0000 | 96.2639 | 70.0101 | 43,212 | 3,119.1458 |

これは**保存した入力をPCで再生した結果**です。新たに実機で読み取った画像のMSEではありません。
手持ちで再読取すると入力が変わるため、同じMSEになるとは限りません。
保存済み検証入力の平均MSEが4モデル中で最小だったH=60を、次の実機確認の初期設定にしています。
この検証チャートは今後の閾値選択にも使うもので、独立した最終評価ではありません。

同一の全0入力に異なる正解色が4つ対応するため、この33組全体のRGB8 MSEの理論下限は
70.0101です。次元を増やすだけでは、このデータ全体でMSE50を下回れません。
3×3だけの0という値を、全33組の精度として報告しないでください。

## 入力と正解RGBの出典

[data/current33.csv](data/current33.csv) に33組と対応する色位置を保存しています。
入力は利用者が新しく測定して送ったセンサ値から得た値です。
正解RGBは、提供された `train_L1_normalization.ipynb` の保存済み正解画像表示から、
各マス内部の均一な11×11画素を調べて復元しました。
元のPNGファイルとの数値照合は未実施です。
復元元の表示画像、抽出位置、ファイルのSHA256、同一入力の制約は

## ファイルと実行

MacのJupyterでは [retrain_current33.ipynb](retrain_current33.ipynb) を単独でダウンロードして、
上から実行できます。33組のデータと学習処理を埋め込んでいます。
NumPyとPyTorchが必要です。再実行ごとに別の保存先を作ります。

リポジトリ一式がある場合は、直下で次を実行できます。

```sh
python3 -m pip install numpy torch
python3 retraining/train_current33.py
```

`retraining/runs/run_.../h40` などへ新たに保存します。
H=100だけなら末尾に `--hidden 100` を付けます。
検証CSVを使う場合は `--validation pruning/validation.csv` で指定できます。

[results/models_summary.csv](results/models_summary.csv) が今回実際に完了した学習の一覧です。
各Hのフォルダにはconst FP32ヘッダ、NumPy配列、PyTorchの学習状態、学習曲線、予測RGB、設定とMSEがあります。
同じ出力先に保存済みヘッダがあれば上書きを拒否します。
今回の実行環境はCPU、1スレッド、Python 3.12.14、PyTorch 2.8.0+cpu、NumPy 2.3.5です。

[results/verification.json](results/verification.json) にPC上の確認結果を記録しました。
全4モデルのヘッダ・NumPy配列・PyTorch保存状態の一致、MSEの再計算、
Notebook全セルの短縮実行と同一seedの再現性を確認しています。
H=60・100のスキャナはホストC++11でASan・UBSanを有効にして実行し、
417入力のRGB8出力がPythonと一致し、b・w・rの操作も通りました。
Arduino実機のコンパイル、起動時チェック、再読取精度は利用者の実行後に別途記録します。

## 次の実機確認

[新しいDenseスキャナ](../hdjsk_retrained/README.md) を使います。
H=60と追加比較用のH=100のヘッダを用意しました。
起動時に12固定入力の計算を確認してから、従来と同じb・w・rで読み取ります。
重み配列のbyte数はビルド全体の使用量とは異なります。
特にH=100の43,212 byteはR4のSRAM 32 KBを超えるため、const配列の配置先と
Arduino IDEの実際のRAM・Flash使用量をビルド時に確認してください。

新しい重みには、古い閾値0.2449や古いCSRヘッダを流用しません。
Denseの実機確認後、各Hの新しいヘッダから閾値を選び直してCSR化します。
旧モデルと旧CSRの記録はそのまま残しています。
