# 低い入力域を追加したV5

V4では、青のNN入力0,0.0362,0.1241に対してH60が0,2,29を出していました。
学習時の青はB入力が約0.219〜0.303で、今回の値はその範囲より低い入力です。
黒の入力0,0,0とは区別があり、読み取った低い入力も教師データへ追加して適応を試みます。

## 学習に含めたデータと役割

提供された元の [result.ppm](../learning_followup/reference_audit/provided/result.ppm) を正解に使います。
SHA256は `582b783b099db5bd6fae89ee0355a17f427fb4a4fc3f2750a8acb8398e5383e2` です。
正解RGBは学習・Arduino内のMSE・先生のサイトの3か所で共通です。

- V4の45組。
- MSEが約1.3万だったV4の全9色読取。
- 最初の白確認1組。
- 新しい校正での白確認3組。
- その校正での青・黒確認2組。

合計60組で、同じ9色のデータです。6回の全チャート読取と、2グループの部分診断に分かれます。
white_check_02の3回と、その続きの青・黒は同じ校正なので同じ分割グループです。
以前の13,000台の失敗結果もそのまま保存しています。
今回までのログはV5の学習・開発へ使ったため、V5の精度確認には新しい読取が必要です。
元の33色全体や未見チャートのモデルとしては扱いません。

## 比較した学習方法

入力3→H→H→出力3、FP32、隠れ層ReLU、線形出力、L1は重みのみ1e-6です。
seed=42、Adam、cosine学習率0.003→0.00003を使います。
追加の白診断が多いため、損失は各正解色の合計重みが等しくなるように計算します。
異なる明るさの読取同士の入力を補間する処理は今回は使いません。

候補はノイズなしと、近くに別の正解色の入力がある場合にノイズを小さくする方法の2つです。
後者は各行の標準偏差を `min(0.005, 別の正解色の入力までの最短距離×0.1)` とします。
新しいデータ中には、青と黒の距離が0.00885程度の組もあるため、従来の0.01を一律に加えずに上限を設けます。
推論時はノイズを加えません。

条件の比較はH60・10,000 epochで校正グループを丸ごと1つずつ外して行いました。
部分診断の誤差は別に保存し、選択は全9色を含む6グループの平均MSEが小さい方法です。
選択結果は [selected_config.json](selected_config.json)、全16結果は [development_holdouts.csv](development_holdouts.csv) です。
選ばれた局所ノイズ法の全読取回平均MSEは **4302.60** で、まだ300を超えています。
これは開発検証で、未使用データの最終評価ではありません。実測で300以下になることを保証する結果でもありません。

その後、全60組でH40・60・100を各50,000 epoch学習して重みを固定しました。

| H | 学習60組上のMSE | 新しいV5の実測MSE |
| --- | ---: | --- |
| 40 | 29.933333 | 未測定 |
| 60 | 1.327778 | 未測定 |
| 100 | 0.550000 | 未測定 |

この表の低い値は学習データ上の値です。MSE300以下の達成と報告しません。
以前のV4とCVに使うデータ・分割が異なるため、両版のCV平均を同じ条件の改善率にはしません。

## 次の新しい読取

[color_retrain_v5](color_retrain_v5) の `color_retrain_v5.ino` と `trained_models_v5.h` を
同じ `color_retrain_v5` フォルダに保存してUNO R4 WiFiへ書き込みます。
シリアルモニタ9600 bpsでRESETし、**FIRMWARE=COLOR_RETRAIN_V5** と **ALL MODELS CHECK: PASS** を確認します。

今の照明条件を保ち、黒b、白wで校正します。
赤・緑・青／黄・水色・紫／黒・灰・白の順で各rを1回ずつ送り、
**ADAPTED CAPTURE START〜ADAPTED CAPTURE END** を保存します。
9色を1回読むと全3モデルのMSEとPPMが出ます。
先生のサイトでは同じ元のresult.ppmを基準とし、Hごとの3×3のPPMと比較します。

センサのLED・ADC・待ち時間・10回平均・黒白正規化・クリップはV4と同じです。
推論はNN入力だけを使います。読取順に正解色をそのまま返す処理はありません。
MSEは出力後に、提供された正解PPMとのRGB差から計算します。
