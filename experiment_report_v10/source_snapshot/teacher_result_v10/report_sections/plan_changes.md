## 計画から変更した実装とその理由

**学習例を増やし、学習時の誤差の扱いを変えた理由。** 同じ色でも校正や読取状態によって入力が変わり、最初の33組だけでは、その変化に十分対応できなかった。そこで追加読取を含む135行を残し、学習時に掛け算・足し算で入力を変化させた。

また、二乗誤差では、大きく外れた入力が学習の更新へ強く影響する。そこで、大きな誤差では増え方が直線になるSmooth L1[5]と、行ごとの正の重要度を使った。大きな誤差の行を削除する代わりに、その影響を調整するためである。結果の評価は引き続きMSEで行い、学習全体や新規読取に大きな誤差が残ったことも報告した。

**正解画像と閾値の条件をそろえた理由。** Notebookの表示画像と先生指定の `result.ppm` は、RGBが異なっていた。同じ予測でも比べる正解が違えばMSEが変わるため、3×3の教師値と評価を先生指定PPMへ統一した。

閾値には、検証MSEの増加5%以下に加えて、学習内9入力でMSE300以下も確認する条件を付けた。利用者の誤差目標を学習内でも確かめるためである。ただし、それだけで別の読取も正確になる保証はなく、新規10回の圧縮方式の平均MSE300以下は達成できなかった。

**次元と保存場所。** 40・60に加えて80・100を比較し、Hを大きくしたときの容量・速度・誤差を調べた。50は未実施であり、80・100の測定で50の比較まで終わったとは扱わない。

授業例の「60次元で可、70次元で不可」は、数値の置き場所や作り方が違えば変わり得る。今回は変更しない定数配列としてモデルを用意し、H100の通常方式で数値配列43,212 byteに対し、静的RAM表示は6,764 byteだった。モデルの数値配列の容量と、RAMの表示を直接同じものとはみなせない。実際の搭載限界と、数値の配置を詳しく示すリンカマップは未測定・未保存である。

**評価範囲。** 独立した最終チャートを使う計画だったが、最終測定日に追加チャート・印刷を利用できなかったため、同じ学習チャートの新規10回読取による対応比較を行った。これは同一入力に対するDense／CSRの差と読取のばらつきを調べるためには使えるが、未知の色への汎化性能の検証を代替しない。紙の読取を繰り返した回数と、保存入力を実機で再生した回数も分けて記録した。
