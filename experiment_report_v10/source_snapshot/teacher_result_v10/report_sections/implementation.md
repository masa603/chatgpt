## 実装アルゴリズムとソースコード

実装は、PCでモデルを準備する部分と、Arduinoで色を補正する部分に分けた。PCでは学習した重みから閾値を選び、小さな重みを0にしてCSRへ変換する。用意した数値は、コードとは別のヘッダファイル（.h）に保存した。Arduinoではこのファイルを読み、同じ入力から通常方式と圧縮方式の結果を出す。保存する数値の形式は、両方式ともFP32でそろえた。

**CSRで保存する3つの配列。** 配列は、数値を番号順に並べたものである。重みの表では、1行が1つの出力先、1列が1つの入力元に対応する。上の行から順に調べ、0以外の重みを `values`、その列番号を `columns` へ追加する。`rows` には、それぞれの行がvaluesの何番から始まるかを記録する。プログラムの番号は0から数える。

\Needspace{14\baselineskip}

説明用に、実測モデルとは別の小さな行列を考える。

$$
W=\begin{pmatrix}0&0.5&0\\-0.2&0&0.1\end{pmatrix}.
$$

$$
\begin{aligned}
\mathrm{values}&=[0.5,-0.2,0.1],\\
\mathrm{columns}&=[1,0,2],\quad\mathrm{rows}=[0,1,3].
\end{aligned}
$$

この表には6個の重みがあるが、0以外は0.5、−0.2、0.1の3個だけなので、それだけをvaluesに保存する。columnsは元の列番号を示す。rowsの[0,1,3]は、「1行目は0番から1番の手前まで」「2行目は1番から3番の手前まで」を意味する。最後の3は、全要素の終わりを示す値である。

例えば入力が $(x_0,x_1,x_2)$ なら、1行目は $0.5x_1$、2行目は $-0.2x_0+0.1x_2$ と計算できる。0を省いても、残った値の使い場所が分かることが重要である。実装では各行の列番号を小さい順に保存し、足す順序を元の行列とそろえた。

`trained_models::predict()`は全接続を調べる通常方式の関数である。`comparison_models::predict()`は、条件番号に応じて通常方式か3層のCSR計算を呼び出す。途中の結果は2本の配列へ一時保存する。

**入力・出力と検査。** `normalizeInput()` は黒白校正値による正規化と0〜1へのクリップを行う。`comparison_models::inferAll()` は1組の入力から全8条件を計算する。出力を整数RGBへ変換してPPMを出力し、`result.ppm` と同じ色順でMSEを求める。出力色を色番号で置き換える処理は行わない。

`validIndices()`は、行の開始位置が順に並んでいるか、終端が保存個数と合っているか、列番号が範囲内かを調べる。`selfCheckAll()`は、同じ入力から想定した数値が出るかを確認する。

検査は2種類ある。**CSRへの保存変換が正しいか**は、枝刈りで0にした後の重みを通常の配列で計算した結果と比べる。**枝刈りで色の誤差が増えたか**は、枝刈り前の通常方式と比べる。変換が正しくても、枝刈りによる誤差は増える場合がある。

主なファイルの役割は次のとおりである。数値ヘッダはコードと別ファイルに保存した。

| ファイル | 主な役割 |
| --- | --- |
| `train.py` | 各Hの追加学習、重みと学習条件の保存 |
| `select_compression.py` | 別の検証128入力による閾値候補の比較 |
| `finalize_compression.py` | 学習内9入力の追加条件を確認し、閾値を固定 |
| `build_program.py` | 固定したDense重み・CSR配列と参照値をヘッダへ出力 |
| `teacher_compare_v10.ino` | 保存入力の実機再生、MSE照合、速度測定 |
| `teacher_fresh_v10.ino` | 黒白校正、新規9色の読取、全8条件の出力 |
| `memory_probe_v10.ino` | 指定した1条件だけを含むFlash・静的RAMビルド |
| `record_fresh_capture.py` | 受領ログの入力・出力・MSEの検算と10回の集計 |
| `record_single_model_memory.py` | 条件名付きIDE表示の保存、容量と削減率の集計 |
