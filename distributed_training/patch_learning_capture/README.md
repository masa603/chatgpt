# 紫・黒・灰・白の追加学習用データを短く記録する

V7の新しい9色実測は全4モデルでMSE300を超え、特に紫・灰・白に大きな誤差がありました。
その3色と比較用の黒について、RAW値と正規化入力を色名付きで追加記録します。
このスケッチはデータ収集専用です。追加学習や新しい補正モデルの実行はまだ行いません。

使うファイルは **[patch_learning_capture.ino](patch_learning_capture.ino) の1個だけ** です。
同名の `patch_learning_capture` フォルダに保存し、UNO R4 WiFiへ書き込みます。モデルの.hは不要です。

1. シリアルモニタを9600 bpsにしてRESETし、`FIRMWARE=PATCH_LEARNING_CAPTURE_V1` を確認。
2. 左下の黒を当てて **b**、右下の白を当てて **w** を送って校正。
3. **紫を当てて p → 黒を当てて k → 灰を当てて g → 白を当てて v** を各1回送信。
4. 出力される **PATCH LEARNING START〜PATCH LEARNING END の4組**をすべて保存。

各文字1回で、その色を3回自動で読みます。START〜ENDまでは同じ色を当ててください。
白は、校正時がw、追加読取時がvです。画像サイズ入力や9色の順番合わせは不要です。
最初から校正し直す場合はnを送信します。

LEDピン・点灯方法・待ち時間・10回平均・従来の0〜1正規化はV7から変更していません。
0〜1へ切り詰める前の正規化値も別の列へ記録しますが、従来の入力列はそのままです。
1回の配置での短い3回読取なので、独立した3回の画像読取とは数えません。
4色だけのデータで全9色MSEを報告したり、300以下の達成と判断したりしません。

[ホストでの確認](verification.json) では、同じ測定関数・誤校正の拒否・色名との対応・各3回の出力・
RAW/正規化の値・再開始・LED消灯をC++11とASan/UBSanで確認しました。
模擬データを新しい実測として保存していません。実機での結果はログ受領後に記録します。
