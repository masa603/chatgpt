# 配布Notebookの画像へ統一した4モデル（V7）

利用者が「配布Notebookの画像に合わせる」を選択し、80次元も追加したため、
**H=40・60・80・100を同じデータ・正解画像・学習手順で学習**しました。
装置や角度の変更は前提にせず、学習データ側を調整しています。

## 正解画像と配布ファイルの確認

新たに提供されたNotebookは `reference_image1_cmyk_large.png` と `reference_image2_cmyk_large.png` を読み、
3×3・6×4へ最近傍で縮小したRGBを正解にしています。
保存済み表示の各色中央11×11画素が一様なことを確かめ、33色を復元しました。
元のPNGファイルのバイトそのものは未入手ですが、Notebookの表示で確認したRGBは記録しています。

以前の `result.ppm` は純色RGBで、配布画像とは違います。例えば緑は前者0,255,0、配布版105,189,69です。
今後の先生のサイトの基準は **[reference_image1_cmyk_3x3.ppm](references/reference_image1_cmyk_3x3.ppm)** に統一します。
これは配布表示の9色をそのままP3へ保存したファイルです。低いMSEを出すために色を調整したものではありません。
旧RGB基準の実測値は保持し、今回のCMYK基準と混ぜて改善率を出しません。
[参照基準の履歴](reference_timeline.md) に経緯を記録しています。

新しいNotebookのX配列は配布例なので、あなたの実測データとして使っていません。
配布物は [materials](materials) に元バイトで保存しました。requirementsは読むだけで一括インストールしていません。
その一覧にはtorchがなく、配布コードを新しい環境で実行する場合は別途導入が必要です。

## 実際の学習データ

[training102.csv](training102.csv) は、既存の実測69組＋最新V6の実測9組＋最初に測定した6×4の24組です。
合計102組・33色です。入力値は全てあなたの既存測定に由来し、正解RGBだけを今回指定した配布画像へそろえました。
前の正解RGBもCSVに残しています。全失敗ログ・旧モデルは保持し、好成績の読取だけを選んでいません。

同じ0,0,0の入力に黒以外の正解色も対応する箇所が残っています。
全102組の無重み学習MSEは、理論的にも143.30未満にはできません。
このような入力を完全に丸暗記すると、新しく読んだ黒まで青く出す問題がありました。
そこでデータを消さず、近傍の正解と整合しにくい例の学習上の重みを小さくする方法を比較しました。
重みは0.1〜1で、0にして捨てる行はありません。これはラベルが間違っているという断定ではありません。

## 学習から外した9色での開発比較

最新V6読取の9色を丸ごと外し、93組で各条件を20,000 epoch学習しました。
最新9色のラベルは、その段階のパラメータ更新・近傍重み計算には使っていません。
ただし失敗ログを見て手法を考え、同じ9色で条件も選んだため、開発用であり独立した最終評価ではありません。

## 選択条件の内容

入力3→H→H→出力3、隠れ層ReLU、線形出力、FP32、重みのみL1係数1e-6を保持しています。
各Hをseed42で最初から初期化し、Adam、cosine学習率0.003→0.00003を使います。
全Hで開発MSEが最小だった「近傍重み＋Huber＋入力揺らぎ」を選び、全102組で50,000 epoch学習しました。

- 近傍重み：自分を除く5近傍で最頻の正解RGBを求め、自分の正解との差から0.1〜1の重みを決定。
- 損失：正規化RGBに対するSmoothL1（beta0.05）の重み付き平均＋L1。評価値は損失関数と区別し、通常のRGB8 MSE。
- 入力揺らぎ：学習時だけ各入力成分へ最大±0.03の一様揺らぎを加え、0〜1へクリップ。近くの信頼度の高い別色をまたがないよう上限を小さくする。

全102組の重み・近傍RGB・揺らぎ幅は [sample_reliability.csv](sample_reliability.csv) です。
そのうち開発時の重みは93組だけから計算し直しています。
推論時は近傍検索・揺らぎ・画像内の位置からの色当て・パレットへの丸めを行いません。
センサのLED・ADC・10回平均・待ち時間・黒白正規化も旧版と同じです。

## 今使う3ファイル

[color_retrain_v7](color_retrain_v7) の `.ino` と `.h` を同じフォルダへ保存し、UNO R4 WiFiに書き込みます。
同じフォルダの `reference_image1_cmyk_3x3.ppm` は先生のサイトの**基準画像**として使います。

1. シリアルモニタ9600 bpsでRESETし、**FIRMWARE=COLOR_RETRAIN_V7** と **ALL MODELS CHECK: PASS** を確認。
2. 黒b、白wで校正。
3. 赤・緑・青／黄・水色・紫／黒・灰・白を各rで1回ずつ読む。
4. **DISTRIBUTED CAPTURE START〜DISTRIBUTED CAPTURE END** を保存。

この1回で40・60・80・100の4モデルのMSEとPPMが出ます。
先生のサイトでは古い純色RGBのresult.ppmから、今回のCMYK版PPMへ基準を切り替えてください。
80次元を含む新しいV7の実測は未受領で、実測300以下の達成をまだ宣言しません。

## 確認記録

[verification.json](verification.json) に33色の正解対応、全チェックポイント・NPZ・ヘッダの一致、
366入力×4モデルのC++計算とRGB8、模擬校正・読取2回・nでの再開始を記録しています。
ASan/UBSan付きでH80の配列も確認し、模擬出力8枚のMSEは先生の元HTMLと一致しました。
模擬データは新しい実測として数えていません。
