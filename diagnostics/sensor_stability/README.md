# 黒→白→黒の生データと待ち時間を確認する

このスケッチは `sensor_stability.ino` の1ファイルだけで動きます。
モデルのヘッダは必要ありません。センサA0、赤D8・緑D6・青D7の配線を使います。

1. Arduino IDEで開き、Arduino UNO R4 WiFiと接続ポートを選んで書き込む。
2. シリアルモニタを9600 baud・改行ありにする。開始案内が見えなければRESETを押す。
3. センサを固定し、3×3チャートの左下の黒を当てて `b` を送信する。
4. `RAW CHECK END` まで約6秒、紙を動かさず待つ。
5. 右下の白へ紙を移動し、`w` を送信してENDまで待つ。
6. 最初と同じ黒に戻し、`b` を送信してENDまで待つ。
7. 3回分の `RAW CHECK START`〜`RAW CHECK END` を保存する。

各回の読取は、LED点灯後の待ち時間10 ms・200 msをそれぞれ5回です。
1チャンネルのセンサ平均は従来と同じ10回、平均内のサンプル間隔は2 msです。
RGBの順番もR→G→Bのままです。1回のRGB読取の後に200 ms待ちます。
両条件で同じ紙面・同じ位置・距離・角度、周囲の照明を保ちます。

最初と最後の黒がそろうか、繰返しで値が動くか、10 msと200 msで差があるかを見ます。
これは入力段階の診断なので、黒白正規化・クリップ・NN推論・PPM出力は行いません。
安定性の判断をする前に、モデルを大きくして色が直るとは扱いません。

この診断では、完全点灯・消灯のためのLED制御を `digitalWrite(HIGH/LOW)` にしています。
元のスケッチの `analogWrite(255/0)` と目的は同じですが、PWMタイマは使用しません。
元コードとは駆動方法が異なるため、この結果だけから従来の差の原因を特定したとは扱いません。
D7/D8が点灯できないという前提も置いていません。コアの版や実配線は別に確認する必要があります。

診断は本番の学習・評価データとは分けて保存します。
まだDense/CSRスキャナの読取条件を変更したわけではありません。
安定する条件が分かったら、両方式へ同じ設定を適用して、新しい測定値で学習し直します。
古いモデル・古い閾値を、そのまま新しい測定条件のモデルとして流用しません。
