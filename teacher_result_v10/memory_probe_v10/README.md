# 各モデル単独のFlash・静的RAMを調べる

40・60・80・100次元のDense／枝刈り＋CSR、計8条件を、**1モデルだけを含むプログラムとしてコンパイル**します。
最終V10の重み・閾値は固定しています。紙の再測定やArduinoへの書き込みは不要です。
クラウドではUNO R4用コンパイラを利用できないため、実際のFlash・RAM値はMacのArduino環境で取得します。

## Arduino IDEで測る（2ファイルだけでできます）

1. `memory_probe_v10` というフォルダを作り、[memory_probe_v10.ino](memory_probe_v10.ino) と [memory_model_v10.h](memory_model_v10.h) を保存します。同じ名前のファイルが重複している場合、末尾の「(1)」などを外します。
2. `.ino`をArduino IDEで開き、ボードを **Arduino UNO R4 WiFi** にします。これまでの実験と同じボードパッケージ・設定を使います。
3. 最初は40次元Denseです。左上の **✓「検証」** を押します。ボードは接続しなくても構いません。
4. 下の出力欄に出る「スケッチが…バイト」「グローバル変数が…バイト」の2行を、**40次元Dense** と書いて送ってください。
5. 冒頭の `#define PROBE_H` と `#define PROBE_CSR` の数字だけを次の表のように変え、各条件で検証します。その他のコード・設定は変えません。

| 条件 | PROBE_H | PROBE_CSR |
|---|---:|---:|
| 40次元 Dense | 40 | 0 |
| 40次元 枝刈り＋CSR | 40 | 1 |
| 60次元 Dense | 60 | 0 |
| 60次元 枝刈り＋CSR | 60 | 1 |
| 80次元 Dense | 80 | 0 |
| 80次元 枝刈り＋CSR | 80 | 1 |
| 100次元 Dense | 100 | 0 |
| 100次元 枝刈り＋CSR | 100 | 1 |

例：40次元CSRは `#define PROBE_H 40`、`#define PROBE_CSR 1` です。
1ファイルに全条件の数値が書かれていますが、コンパイル時に選んだ1条件だけが残ります。
条件ごとの結果をまとめて送っても、1条件ずつ送っても構いません。

## Macで8条件を自動測定する場合

上の2ファイルに [run_memory_builds.py](run_memory_builds.py) を加えて同じフォルダへ置きます。
Arduino IDE 2付属または既存のArduino CLIと、インストール済みのUNO R4ボードパッケージを使用します。
追加のPythonライブラリは不要です。ボードのアップロード・センサ測定・ソフトのインストールは行いません。

そのフォルダをターミナルで開いて実行します。

```sh
python3 run_memory_builds.py
```

Jupyter Notebookを同じフォルダで開いているなら、セルで次を実行できます。

```python
%run run_memory_builds.py
```

終わると `compile_results/日時/` に `single_model_memory.csv` と `environment.json` ができます。この2ファイルを送ってください。
失敗した条件があれば、同じフォルダの該当する `h40_dense.json` なども送ってください。
CLIを検出できない場合は、上のArduino IDEの手順で測定できます。
自動処理は元の2ファイルを書き換えず、8条件の生成コード・コマンド・容量元ログ・環境情報を保存します。

## 報告書での値の扱い

「スケッチが…」は、この共通の測定プログラムに選んだ1モデルを入れた場合の**プログラム全体のFlash使用量**です。
「グローバル変数が…」は**静的RAM使用量**です。両者ともIDE／CLIのビルド結果を記録します。
全8モデル入りの既存コードの187888byte／6740byteなどとは別の測定です。

数値配列は `const` で、Arduinoコアや共通処理も含むため、静的RAMは圧縮してもほとんど変わらない場合があります。
推論の中間配列は元のV10と同じ100要素×2、宣言量800byteです。関数内のローカル変数なのでIDEの静的RAMには含まれません。
IDEに出る「ローカル変数で使える…」は静的RAMを引いた残り容量であり、実際に使ったスタックの最大量ではありません。

PCでは8条件それぞれ626入力の推論・RGB8一致、1条件だけが残る構成、最適化後も推論と配列が残ることを検査しています。
PCの実行ファイルサイズはArduinoのFlash・RAM値として使用しません。
